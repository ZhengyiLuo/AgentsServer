# Cursor CLI local import

## Contract

- Keep `local_session_import_v1` unchanged for existing Claude/Codex clients.
  A client that understands Cursor checks `local_session_import_cursor_v1`
  (`version: 1`, `history_mode: initial_text_snapshot`) and requests
  `GET /api/local-sessions?include_cursor=true`. Without opt-in, no Cursor rows
  are returned. The bulk endpoint accepts `backend: cursor` and reports success
  only after the text history is durably staged and committed.
- Retain the provider session ID and workspace. Continuation uses the existing
  Cursor `--resume` runner, not a fresh session primed with imported text.
- Prefer native metadata titles, then a human-message preview. `New Agent` is
  a placeholder. Discovery does not call a model to manufacture missing titles.
  Display a valid native name unchanged apart from bounded display sanitization;
  otherwise use the first user message (not the latest message or tool output).
  Do not prefix the project: the unchanged `cwd` field carries that information.
  If neither title nor user text is available, use `Cursor chat <short ID>`.
  Sanitize the database name before trying the native sidecar fallback.
  Import keeps the chosen label, including native names such as `New chat` or
  `Untitled`; it does not schedule automatic renaming or change Cursor's data.
  Preview extraction recognizes complete AgentsDock instruction/current-prompt
  envelopes, length-delimited fork memory and validated authority/tool-binding
  suffixes. A bare bracket heading or an incomplete/lookalike envelope is not
  stripped. This display-only cleanup does not rewrite imported history or
  change history reconciliation keys.
- Apply current/cross-instance ownership filters before the list limit and
  recheck during import. Do not expose subagents, empty sessions, ambiguous IDs,
  missing workspaces or unreadable/mismatched native stores.
- Import an initial snapshot of public user/assistant text. Strip native user
  prompt wrappers and omit tool-result/context reinjections. Preserve legitimate
  repeated messages. Unknown or changing input fails without a partial chat.
  Manual server-side resume can request the same initial history; legacy desktop
  manual-ID resume retains its previous no-history behavior. Picker resume uses
  the bulk import path with validated metadata.

## Supported source and limitations

Verified private-format adapter for Cursor CLI `2026.09.18-9a7762b`:

1. Configuration root: `CURSOR_CONFIG_DIR`, then `XDG_CONFIG_HOME/cursor`, then
   `~/.cursor`. `chats/<md5(cwd)>/<id>/meta.json` schema 1 establishes the exact
   workspace, conversation presence and subagent status.
2. Read-only `store.db`, `meta` key `0`, hex-encoded JSON: verify `agentId`, read
   `name` and reject `subagentInfo`. No blob table, encryption key or private
   conversation content is read/decrypted.
3. Public JSONL export:
   `<data-root>/projects/<native-workspace-slug>/agent-transcripts/<id>/<id>.jsonl`.
   Data root is `CURSOR_DATA_DIR`, falling back to `~/.cursor`, independently
   of `CURSOR_CONFIG_DIR`. Read only bounded complete
   records from a stable file snapshot. Do not infer workspace from the slug.

This is **not** Cursor IDE/cloud history, a transcript migration, complete tool/
reasoning/image replay, or automatic synchronization of later edits made in the
native CLI. The export lacks stable message IDs and can be rewritten; it is not
passed through the append-only Claude/Codex reconciliation machinery. A missing
sidecar/export is skipped rather than generated by invoking the CLI. Archive
semantics not represented by this verified format are not guessed.

The shared scanner still has bounded traversal and a 500-row response maximum;
there is no new pagination promise. Cursor support requires a compatible client.
Old clients remain usable but do not show these new rows.

## Verification

`test_cursor_local_import.py` covers exact ID/workspace binding, title fallback,
read-only reads, unsafe/corrupt/missing inputs, subagent filtering, ownership,
legacy opt-out, stable text snapshots, duplicate preservation, durable import,
native resume argv, idempotence and rollback. Run with isolated home/state roots
as required by the [provider checklist](PROVIDER_INTEGRATION_CHECKLIST.md).

Keep fixture results, live CLI continuation and actual client acceptance separate
in the PR; adapter tests alone do not establish native runtime or GUI parity.

and 209 Cursor/history/title regressions passed. An isolated native Electron
source app exercised the real picker and authenticated bulk endpoint against a
disposable server. A real Cursor CLI request supplied the original conversation;
after import and app reopen, a contextual follow-up returned its earlier code
word using the same native ID/workspace (exit 0). No private blobs were read by
AgentsServer. Native execution also verified independent `CURSOR_DATA_DIR` and
`CURSOR_CONFIG_DIR` handling. Mobile and packaged-app acceptance are not claimed.

An authenticated test-instance restart and read-only native-metadata/list check
